# GSB Bugfix Task
## 题面
手游热更打包最近连续出事故：某个 UI 包先于它依赖的图集打进清单，启动时直接报资源缺失；两个模块互相引用时构建脚本没有报错，而是随机挑一个先编；依赖里写了一个还没登记的包名，流程照样往下走，直到运行期才炸；同样的工程跑两次，产出的资源顺序完全不同，增量对比全是噪音；同一个依赖在列表里写了两遍，构建次数也跟着翻倍。asset_dependency_graph.py 的 AssetGraph 提供 add_asset、build_order、missing_deps、cycles 和 state。资源名必须是非空字符串且不能重复，依赖列表里的名字不能重复；允许先登记依赖、稍后再补上对应资源，补登记之后缺失记录要自动消失；build_order 返回依赖在前、被依赖者排在其后的拓扑序，每个资源出现且只出现一次，同一层按字母序打破平局，出现缺失依赖或环时抛 ValueError；missing_deps 返回按资源名与依赖名排序的缺失对；cycles 把每个强连通分量整理成升序列表并按首元素排序，自环也要算一个环；state 暴露排序后的依赖表，修改快照不能影响图本身。

## 运行方式
```bash
python -m pytest tests -q
```
